Il problema N+1

Questa pagina dimostra il problema delle query N+1 nell'accesso a relazioni JPA/Hibernate caricate in modalità lazy (animale.getRecensioni()), e come risolverlo con JOIN FETCH.

Senza soluzione N query

Caricando la lista di animali con findAll() e poi accedendo, per ognuno, alle sue recensioni fuori da un'unica query, Hibernate esegue:

  • 1 query per caricare tutti gli animali
  • +1 query per ogni animale, per caricarne le recensioni (lazy loading)
SELECT * FROM animali; -- per ciascun animale: SELECT * FROM recensione WHERE animale_id = ?;

Con N animali nel database, il totale è N+1 query.

Con soluzione: JOIN FETCH 1 query

Nel repository, la query personalizzata findAllWithRecensioni() carica animali e recensioni insieme, in una sola interrogazione al database:

@Query("SELECT DISTINCT a FROM Animale a LEFT JOIN FETCH a.recensioni") List<Animale> findAllWithRecensioni();

Indipendentemente dal numero di animali, viene eseguita sempre 1 sola query: questa è la query usata per i dati qui sotto.
